# Конфигуратор страницы: первый рабочий вариант

## Визуальный редактор

Создание и редактирование доступны на `/:locale/pages/:slug/edit`. Кнопка
«Редактировать» на странице видна администратору с полными правами.
Заголовок и описание используют общий компонент с обычной страницей и
редактируются по нажатию. Настройки колонок находятся в шапке таблицы:
подпись, поле БД, формат, перемещение и удаление. Рядом — добавление колонок,
размер страницы и сортировка. При создании сначала выбирается таблица БД;
у существующей страницы источник сохраняется.

Изменения остаются в локальном черновике до «Сохранить». При уходе редактор
предупреждает о потере правок. Сохранение существующей страницы использует
`PUT /api/pages/:id` с исходной `revision`: конфликт не затирает черновик.
Создание использует прежний атомарный `configureForMenu`.

Предпросмотр показывает до пяти строк сохранённой конфигурации. Запрос
использует допустимый размер страницы; новые поля и новая сортировка
отображаются с данными после сохранения. Поля, используемые в деталях записи,
не удаляются из конфигурации при удалении колонки списка.

Подключение существующей страницы остаётся отдельным диалогом. Описанный
ниже пошаговый сценарий создания сохранён в прежнем компоненте, но кнопка
«Настроить страницу» теперь открывает визуальный редактор.

## Пользовательский сценарий

Пункт меню без привязанной страницы открывает пустое состояние с кнопкой «Настроить страницу».
Кнопка открывает существующий компонент Modal. В нём два сценария:

1. Новая страница: выбор таблицы, название, описание → выбор и порядок полей,
   подписи, форматы, уникальный ключ, сортировка и размер страницы → «Создать и подключить».
2. Существующая страница: поиск с постраничной загрузкой → выбор → «Подключить страницу».

После сохранения модалка закрывается и DataPage заново получает документ страницы.
Полный renderer таблицы и детальной карточки — следующий отдельный этап;
сейчас DataPage показывает название, описание и число настроенных колонок.

## Каталог отдельно от страниц

`GET /api/schema-catalog` — отдельный admin-only API со своим контрактом
`@auto-admin/contracts/schema-catalog`. Читает сохранённый каталог через его кеш,
не запускает сканирование базы. Возвращает ресурсы, поля, совместимые форматы
и подходящие уникальные ключи. Удалённые ресурсы и поля исключаются.
Значения колонок, SQL default/generated expressions и служебная история сканов не передаются.

Системные таблицы видны с отметкой, но не выбираются как источник обычной страницы:
существующий серверный валидатор и Query Engine не разрешают такой обход специальных API.
Отсутствие каталога не маскируется пустым списком: API возвращает 409 SCHEMA.CATALOG_REQUIRED.
Модалка предлагает «Просканировать базу данных» через существующий POST /api/access/scan,
затем повторяет GET каталога. Для последующих изменений структуры есть «Обновить каталог базы».
GET сам не запускает сканирование. Сканирование меняет только служебный каталог, а не таблицы пользователя.

## Сохранение

`POST /api/pages/for-menu/:slug` принимает одну из команд:

- `{ mode: 'create', page: { name, description, config } }`;
- `{ mode: 'existing', pageId }`.

Сервер проверяет администратора, валидирует конфиг по актуальному каталогу,
затем внутри транзакции повторно проверяет активные права администратора.
Создание страницы, привязка к меню и обе записи аудита входят в одну транзакцию.
Существующая страница блокируется перед пунктами меню — такой же порядок у удаления и обычного сохранения меню.
Уже назначенная страница не перезаписывается: конкурентный запрос получает 409.
Несуществующий или скрытый неактивным предком пункт получает 404.

## Где читать код

- `client/src/features/page-configurator/PageConfigurator.tsx`: форма, загрузка, выбор, сохранение.
- `client/src/features/page-configurator/model/build-page-config.ts`: черновик формы → валидный CreatePageData.
- `client/src/shared/api/schema-catalog/index.ts`: клиент каталога.
- `server/src/modules/schema-catalog/catalog-presenter.ts`: внутренний каталог → безопасный публичный DTO.
- `server/src/modules/pages/page.service.ts`: транзакционная операция configureForMenu.

Новые компоненты используют только useState и useEffect. useMemo/useCallback/useRef
для этого сценария не обязательны; существующий Modal уже управляет dialog через свой ref.
